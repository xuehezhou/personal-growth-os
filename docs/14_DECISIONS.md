# 关键决策记录

本文记录影响多个模块且需要长期保持一致的选择。状态为“已采用”表示当前实现；“目标决策”表示方向已确定但尚未完成。

## ADR-001 使用 Streamlit 本地单体

- 状态：已采用
- 问题：个人本地工具需要快速形成可交互闭环。
- 决策：使用单个 Python/Streamlit 进程承担 UI 和业务调用。
- 原因：部署简单、学习成本低、当前没有多用户并发需求。
- 代价：前后端边界不明显，复杂交互和多端同步能力有限。
- 复评条件：明确出现多客户端、远程集成或多人权限需求。

## ADR-002 SQLite 是当前真实数据源

- 状态：已采用
- 决策：业务数据保存在 `data/growth.db`，不增加云数据库。
- 原因：本地优先、隐私可控、备份直接、运维成本低。
- 代价：多设备同步和并发写入有限，迁移与备份责任在本地。
- 约束：数据库文件不提交版本库；结构变更先备份并迁移验证。

## ADR-003 每日任务采用“模板 + 实例”

- 状态：已采用
- 决策：`recurring_task_templates` 保存规则，`tasks` 保存每天的结果。
- 原因：每天可以独立完成、顺延、记录实际分钟，同时保留历史。
- 不变量：同一模板同一天最多物化一个实例；停用不删除历史。

## ADR-004 睡眠允许任务与习惯双轨记录

- 状态：已采用
- 决策：“保持 8 小时睡眠”可以既是每日任务，也是习惯。
- 原因：任务表达当天承诺，习惯表达长期实际表现，两者用途不同。
- 约束：UI 和统计必须解释口径，不能把两者分钟简单相加为总投入。

## ADR-005 规划器保持确定性和用户可控

- 状态：已采用
- 决策：当前 Planner 只根据规则给建议，不自动改写用户任务。
- 原因：任务优先级和人生选择需要可解释、可撤销。
- 复评条件：未来 AI 建议也必须先预览、可编辑并由用户确认。

## ADR-006 Daily Journal 是核心目标能力

- 状态：目标决策
- 决策：在现有每日复盘之外增加可浏览、可搜索的日记历史。
- 原因：成长系统不仅需要结果字段，也需要连续的事实和思考记录。
- 约束：保留现有 `daily_reviews` 数据并设计兼容关系，不用重建数据库解决。

## ADR-007 Quick Capture 使用收件箱模式

- 状态：目标决策
- 决策：未分类内容先进入独立收件箱，再转任务、日记或归档。
- 原因：捕获时不应被复杂分类打断，整理时又必须保持可追踪。
- 约束：转换失败时原始捕获不能丢失，重复提交不能生成重复目标记录。

## ADR-008 目标变更保留版本

- 状态：目标决策
- 决策：重要目标更新同时保存版本快照和变更原因，结束使用归档而非抹除。
- 原因：个人成长的重要信息是方向如何变化，而不只是当前值。
- 约束：主记录和版本必须在同一事务写入，历史任务关联持续可读。

## ADR-009 当前不建设 HTTP API

- 状态：已采用
- 决策：内部页面直接调用 service，不为了架构形式增加 REST 层。
- 原因：当前只有本地单客户端，API 不解决真实问题。
- 复评条件：出现多端、第三方集成、远程同步或独立前端。

## ADR-010 AI 采用可选、最小数据、人工确认原则

- 状态：目标决策
- 决策：AI 只用于总结和建议；默认不上传私人数据，不直接执行重要写操作。
- 原因：日记和目标高度敏感，模型输出也具有不确定性。
- 约束：明确显示发送范围、允许关闭、重要变更由确定性 service 校验并由用户确认。
