# 开发计划

从 V0.2 开始采用“一个小版本、一个明确目标、一次可恢复 Git 提交”的方式推进。优先级顺序始终是：数据安全、正确性、可使用、低操作成本、体验、代码优雅。

## P0：长期使用的必要闭环

| 版本 | 唯一目标 | 当前状态 | 完成标准 |
|---|---|---|---|
| V0.2 | 数据安全与数据库稳定 | 已完成 | Schema 有版本；迁移前自动备份；测试不写真实库；备份可验证 |
| V0.3 | Goals / Direction 用户所有权 | 下一步 | 方向和目标由用户输入；中性空状态；旧数据不被自动覆盖 |
| V0.4 | Goals History | 待开发 | 修改目标/方向同时保存时间、内容与变更原因 |
| V0.5 | Quick Capture / Inbox | 待开发 | 5–10 秒保存；默认 Inbox；原文不因转换失败丢失 |
| V0.6 | Daily Journal | 待开发 | 一天一页；写得进去、存得下来、重新打开还在 |
| V0.7 | 历史日记 | 待开发 | 可按日期打开任意一天；不同日期互不覆盖 |
| V0.8 | Today 整合 | 部分已有 | 系统、用户、临时任务统一；完成率按当天全部真实任务计算 |
| V0.9 | 阅读 / Habit / Review 与 Journal 联动 | 待开发 | 当天行为可正确反映到当天 Journal，不重复统计 |
| V0.10 | 提醒系统稳定化 | 基础已有 | 任务、22:30、22:50、23:00 提醒均按 Settings 生效 |
| V0.11 | 备份 / 恢复稳定化 | 部分已有 | 完成恢复演练、恢复前备份和更清晰的恢复入口 |

### V1.0 门槛

V1.0 不是“代码全部写完”。必须真实连续使用至少 7 天，并满足：没有关键数据丢失，日记和历史正常，任务统计、灵感、目标、阅读和复盘可持续使用，没有阻碍日常使用的严重 Bug。

## P1：使用体验增强

- 日记全文搜索；
- 周复盘与月复盘；
- 更完整的 Dashboard；
- 数据导出；
- 灵感批量整理；
- 目标进度反馈；
- 提醒与 UI 细节优化；
- 习惯和书籍的编辑、停用、排序与安全删除。

## P2：AI 能力

- AI 每日总结和周复盘；
- 长期行为模式与延期原因分析；
- 目标调整和第二天计划建议；
- 阅读复盘；
- Personal AI Coach。

AI 只提供可预览的建议，不直接控制删除、状态机或重要数据写入；发送私人数据前必须由用户选择。

## P3：长期探索

- 手机端；
- 云端与多端同步；
- Personal Agent；
- MCP 集成；
- 更完整的 Personal Life OS。

## 每轮开发闭环

```text
读取规则与相关文档
→ 检查真实旧代码和 Git 状态
→ 明确唯一 Scope 与数据库影响
→ 开发
→ 自动测试
→ 启动应用并手工验收
→ 修复后再次测试
→ 只同步相关文档和 CHANGELOG
→ Git diff 复核
→ 创建一个可恢复 Commit
```

## 当前唯一下一步

V0.3 Goals / Direction 用户所有权：停止为已有数据库补写系统决定的方向和目标；为新用户提供中性问题提示与空状态，同时保留当前用户已经存在的数据。
