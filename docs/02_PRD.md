# Personal Growth OS 产品需求文档（PRD）

版本：文档基线 1.0  
产品阶段：可用的 V1 基础版  
状态标识：✅ 已实现、🟡 部分实现、⬜ 未实现。

## 1. 产品背景

用户同时学习技术、做项目、阅读、运动、处理生活事务并思考长期方向。现有信息分散后，每天容易被临时事项带走，计划与执行、记录与复盘彼此断开。

## 2. 用户问题

- 学习主题太多，不知道今天最重要的是什么。
- Todo 只记录任务，不记录生活、思考和方向变化。
- 计划生成后缺少执行、验收和未完成反馈。
- 阅读、习惯、项目和生活的数据互相隔离。
- 想法来得快，缺少低摩擦收集入口。
- 目标变化后，旧认知会被覆盖，无法回看成长轨迹。

## 3. 核心用户场景

1. 早上打开 Today，确认当前方向和今天主任务。
2. 白天执行任务，临时事项加入今天，完成时按标准验收。
3. 随时记录灵感，之后再决定用途（目标场景，未实现）。
4. 阅读或锻炼后记录进度和习惯。
5. 晚上记录生活、学习、问题和明日调整。
6. 每周查看统计和历史，调整目标。

## 4. 产品目标

- 30 秒内回答“今天最重要的一件事是什么”。
- 所有今日任务使用同一完成率口径。
- 每一天的数据独立保存，不覆盖其他日期。
- 用户自主决定目标，系统只提供建议与结构。
- 长期数据可备份、可恢复、可迁移。

## 5. 核心流程

```text
方向 → 目标 → 今日任务 → 执行 → 验收 → 记录 → 复盘 → 历史 → 调整
```

目标补充流程：

```text
灵感 → 快速收集 → Inbox → 整理为任务 / 日记 / 目标 / 成长思考
```

## 6. 功能需求

### 6.1 Today ✅

- 显示日期、今日主任务、完成数、完成率、计划与实际分钟。
- 按上午/下午/晚上/全天展示。
- 区分系统计划、自主安排和每日任务，但统计使用全部任务。
- 提供快速任务入口、容量警告、规则建议、习惯与提醒。
- 主任务最多突出一个；重要任务数量应受产品规则约束，目前只通过数据优先级间接控制。

验收：当天手动新增任务后，刷新 Today 仍存在且总数增加。

### 6.2 Goals / Direction 🟡

- 长期方向、阶段目标、当前目标、主要/次要矛盾、当前优先、暂时不做均由用户编辑。
- 目标支持长期/阶段/本周三级、父目标、时间、进度、成功标准和状态。
- 同时建议只有一个当前最高优先目标。
- 目标内容不得永久写死。初始化可提供“示例”，但必须明确标记并允许清空。
- 目标历史：每次重要方向修改应新增版本，而不是覆盖。⬜
- 目标归档和历史查看。⬜

当前差距：首启示例内容较具体；方向表是单例且覆盖更新。

### 6.3 Tasks ✅

- 创建、编辑、完成、删除、延期、放弃。
- 字段：名称、描述、分类、优先级、日期、起止时间、时间段、预计/实际分钟、验收标准、状态、完成比例、备注、目标关联。
- 今日自主任务自动进入 Today。
- 每日重复任务每天最多生成一个实例，可停止未来生成并保留历史。
- 连续延期 3 次提示拆分、降级或放弃。
- 睡眠可不计入白天容量。

### 6.4 Quick Capture / 灵感闪现 ⬜

- 所有主要页面提供“💡 记一下”或固定入口。
- 默认只要求一段内容，5–10 秒内保存。
- 默认 `category=未分类`、`status=Inbox`。
- Inbox 支持编辑、删除、保留、处理、归档。
- 可转换为 Task、Journal、Goal、Growth Thought，并记录 `converted_type`、`converted_id`。
- 转换必须是受控操作；删除需确认。

### 6.5 Daily Journal 🟡

- 产品原则：一天一页。
- 目标内容：状态、主任务、上午/下午/晚上、用户任务、实际发生、学习、生活、阅读、锻炼、灵感、成长思考、优化、复盘、明日主任务。
- 当前只有 Daily Review 表单和自由文本；任务、习惯、阅读没有聚合成当天快照。
- 昨天与今天不得互相覆盖。
- 未来应支持历史列表和 Snapshot。

### 6.6 Books 🟡

- 初始化推荐书单覆盖习惯、职业、表达、决策、商业、金融。
- 支持当前阅读、待读、完成、页数、时间、日期、笔记和轻量反思。✅
- 同时最多 1 本主书 + 1 本轻阅读。✅
- 用户新增、删除、调整顺序。⬜
- 推荐书单是初始化数据，不应成为不可修改的代码常量。

### 6.7 Habits 🟡

- 默认建议：睡眠、阅读、锻炼、技术学习、项目实战、复盘。
- 新增、自定义目标分钟、按日期打卡、备注、连续天数。✅
- 编辑、停用、恢复、删除。⬜
- 任务与习惯可记录同一主题：任务管当天结果，习惯管长期连续性。

### 6.8 Review ✅ / Weekly Review ⬜

- 每日复盘包含实际发生、主任务、收获、学习/生活优化、问题、状态、成长思考、时间浪费、明日主任务和自由日记。
- 不强制所有问题都填写。
- 周复盘、重复问题识别和趋势总结尚未实现。

### 6.9 Dashboard 🟡

- 7/30 天完成率、实际分钟、项目、阅读、锻炼、连续学习、领域分布。✅
- 当前以任务表为主，未来应整合阅读日志、习惯、复盘和 Journal。

### 6.10 Reminder 🟡

- 任务提前 5/10/15/30 分钟、任务超时、复盘、睡眠准备、洗漱和夜间收尾。✅
- 睡眠时间和准备分钟可配置。✅
- 应用关闭后的系统通知。⬜

### 6.11 Settings 🟡

- 当前支持任务提醒、提前分钟、睡眠提醒、睡觉时间、准备分钟、复盘时间。
- 未来支持容量、备份目录、数据导出和默认 Journal 设置。

### 6.12 数据安全 🟡

- 所有数据保存在本地 SQLite。✅
- Schema 修改必须兼容旧数据，禁止删除数据库重建。✅ 原则已建立
- 一键备份、恢复验证、迁移版本记录。⬜

## 7. 非功能需求

- 本地单用户优先，默认只监听 `127.0.0.1`。
- 页面操作后有成功、错误、空状态或提醒反馈。
- SQL 使用参数化查询。
- 重要写入失败不得静默吞掉异常。
- 新功能必须有持久化验证和旧功能回归测试。
- 文档必须区分当前实现与目标设计。

## 8. 本版本不做

多用户、团队协作、云数据库、社交、支付、复杂权限、微服务、真实 AI 自动决策、移动端原生 App。
