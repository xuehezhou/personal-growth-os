8. 17 本初始化书单、阅读状态、页数、时长、轻量反思和主书/轻阅读限制。
9. 按日期保存每日复盘和自由文本。
10. 7/30 天任务完成率、任务投入时间、分类分布和学习连续天数。
11. 任务开始/超时、复盘、睡眠与夜间收尾的应用内提醒。
12. SQLite 持久化、外键、唯一约束、版本化迁移、迁移前自动备份和设置页手工备份。
13. 13 项自动化测试，包括核心业务、持久化、数据安全和 8 页面冒烟测试。
14. Git 仓库已建立，`main` 跟踪当前代码基线。

## 部分实现

| 能力 | 当前实现 | 缺口 |
|---|---|---|
| Daily Journal | `daily_reviews` 按日期保存复盘与自由文本 | 没有完整“一天一页”、状态/学习/生活/灵感聚合和历史页 |
| Goals | 可新增、编辑、完成、暂停，支持父目标 | 没有历史版本、归档、快照；方向更新会覆盖旧值 |
| Books | 可修改状态、页数、日期、笔记并写阅读日志 | 不能新增、删除、重排；推荐数据仍由初始化代码维护 |
| Habits | 可新增和打卡 | 不能编辑目标、停用、恢复或删除 |
| Planner | 可解释建议与容量检测 | 不会按目标自动创建完整的每日系统计划 |
| Reminder | 页面打开时检查提醒 | 应用关闭后不工作，没有 Windows 系统通知 |
| Dashboard | 基于任务统计 | 没有合并 `reading_logs`、`habit_logs`、复盘与生活数据 |
| 数据恢复 | 已有迁移前自动备份和手工备份 | 恢复仍按文档手工执行，没有一键恢复与恢复演练 UI |

## 重复设计

- 睡眠同时存在于每日任务和习惯。这是用户明确选择的双轨设计：任务用于当天执行，习惯用于长期连续性；并非需要删除的重复。
- `books.today_minutes` 与 `reading_logs` 都记录阅读时间，但前者没有按日期重置，职责重叠且含义不准确。
- Goals、Review、Books 页面直接写 SQL，而 Tasks/Habits/Reading 主要通过 Service，业务入口不统一。

## 不一致设计

1. 产品目标要求用户自己定义人生方向，但 `_seed_defaults()` 和 `_seed_goals()` 首次启动会写入具体 AI 成长示例。它们可编辑，但容易被误认为用户真实选择。
2. 目标架构期望 `UI → Service → Database → SQLite`，真实代码还存在 `UI → database.execute()` 快捷路径。
3. 早期页面和文档曾把基础闭环称作 V1；当前已统一为 V0.2，V1.0 需经过 7 天真实使用验收。
4. 任务删除文案写“不可撤销”，但每日任务实例实际会被标记为“已放弃”，不会物理删除。

## 技术债

- `find_main_task()` 只排除“已放弃”，已完成主任务仍可能被首页突出显示。
- `books.today_minutes` 持续累加，不代表真正的“今日分钟”。
- Dashboard 的阅读和锻炼来自任务表，不一定等于阅读日志或习惯日志。
- `pages/today.py`、`pages/goals.py`、`pages/tasks.py` 有 `\\n+` 文本残留，影响显示质量。
- 数据库 Schema、默认数据和迁移注册仍集中在 `database.py`，文件责任偏多。
- 默认示例任务只在首次启动当天生成；“系统计划”并不是持续的每日自动计划。
- 测试未覆盖目标/方向历史（尚无此功能）、真实恢复演练、书籍新增删除、习惯编辑删除等目标能力。
